The Coder-480B uses the same `tokenizer.json` as every Qwen3 model (same SHA-256), so Qwen3 drafters can feed it; it only ships a different chat template, which its runs use. Qwen3.5 has its own tokenizer (248,320 tokens vs 151,936), so it is a separate chain. No open Qwen model is above 700B.

Fairness: temperature 0, max_tokens 256, 48 prompts (28 code, 20 chat, math and short answers), 2 warm-up prompts not counted, cold starts logged apart, a cold prefix cache for every prompt in every run. Lossless check: every spec run is compared token by token with the big model alone.

## 5. Ranked improvements

Gain is expected, not measured, unless a file is named.

| # | Change | Expected gain | Effort | Risk | Evidence |
|---|---|---|---|---|---|
| 1 | Put drafter and verifier on one box (vLLM draft model, n-gram, EAGLE-3 or MTP) instead of across the internet | Removes the per-round round trip; papers report 2x to 3x on code | Low (a vLLM flag) | Low | Leviathan et al., arXiv 2211.17192; EAGLE-3, arXiv 2503.01840; `spec_results.md` (the loss was the round trip); Phase A measures it |
| 2 | Skip the 30B for open chat with a cheap prompt check | Replay: 94% of chats climbed anyway, so the 30B call was wasted time | Low | Low | `results_replay.md` |
| 3 | Check near-repeat cache hits with a test or a judge before serving | Replay: 82 of 97 near-repeat pairs were not interchangeable | Medium | Low | `results_replay.md`, `results_bank.md` |
| 4 | Keep a self-hosted GPU warm only when traffic keeps it busy | Avoids $108.96 a day idle | Low | Low | `results_cost_case_h200.md`, `results_modal.md` |
| 5 | Route by a learned quality estimate instead of token probability | The learned router tied the gate at 70%; needs better features | High | Medium | `results_research_router.md`; FrugalGPT, arXiv 2305.05176; RouteLLM, arXiv 2406.18665 |
| 6 | Drop LoRA on 763B answers in this form; keep retrieval of checked answers | LoRA lost 3.9 points | Low | Low | `results_distill.md` |
| 7 | Tree drafts or Medusa-style heads for same-box spec | Papers: a further 1.2x to 1.5x | High | Medium | Medusa, arXiv 2401.10774; SpecInfer, arXiv 2305.09781 |

## 6. Open questions for the user

1. Is the goal lower cost or lower latency? The ladder cuts cost on repeats and trivial code and raises latency on chat.
2. Serve a big model ourselves (needs steady traffic) or stay on Crusoe tokens, which are cheaper than an idle H200?
3. Should speculative decoding enter the product at all? Only a self-hosted vLLM big model can verify; the 763B cannot.
4. Which quality gap matters most: hard code (78% vs 92% on the V100 30B) or open chat?
5. Delete the speculative-decoding weight volumes after review? Phase A alone is about 1.2 TB, about $110 a month.
6. What should the Modal spend limit be? Phase A needs about $75 of GPU time and Phase B about $120 (estimates, list prices).
